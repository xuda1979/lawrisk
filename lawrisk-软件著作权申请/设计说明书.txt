────────────────────────────────────────
1  引言
────────────────────────────────────────
1.1  编写目的
本说明书描述 LawRisk 合同风险审阅软件的总体设计、模块划分、接口设计与详细设计，
供软件开发、测试、维护人员及软件著作权审查人员理解本软件的设计思路与实现原理。
本软件面向中小律所的合同风险分与条款差异比对场景，提供确定性、可解释、可复现的
本地化合同审查能力。

1.2  项目背景
中小律所在合同初筛阶段需要快速判断一份合同的风险高低与条款偏离情况。市面上由大
模型驱动的审查工具成本高、结果不可解释、且需要将客户机密合同上传至第三方。本项目
以"低成本、可复现、全程本地、每条结论可举证"为设计目标，实现一套基于字典/正则/
关键词规则的确定性风险引擎，并配套条款差异比对、模板库对照、报告导出与离线命令行。

1.3  术语与缩略语
- CPCC：中国版权保护中心（China Copyright Protection Center）。
- 规则引擎（Risk Engine）：将文档段落逐条与规则匹配、累计扣分并生成风险报告的模块。
- 段落（Paragraph）：文档中按空行分隔的文本单元，本系统评分与比对的最小文本单位。
- 章节（Section）：以标题（第X条/第X章/数字编号标题等）识别的文档结构单元。
- 差异树（Diff Tree）：两份文档按章节对齐后的段落级增/删/改层级结构。
- 确定性哈希（deterministic_hash）：对"内容 + 引擎版本"做 SHA-256 得到的散列值，
  用于证明相同输入必然得到相同输出。
- 维度（Dimension）：风险分类，共 4 类——commercial（商务）、liability（责任）、
  data（数据合规）、export（出口管制）。
- 严重度（Severity）：规则扣分权重，分为 1/2/3 三档（轻/中/重）。

────────────────────────────────────────
2  总体设计
────────────────────────────────────────
2.1  系统结构
本软件采用经典的前后端分离架构，并支持"单进程单端口"的简易部署模式。
总体层次如下（自底向上）：

  1) 文本解析层（lawrisk.parser / lawrisk.textutil / lawrisk.fields）
     负责把 DOCX / PDF / TXT 等不同格式的合同文档解析为统一的段落列表、
     headings 列表与关键业务字段（币种、期限、准据法、仲裁地）。
  2) 风险引擎层（lawrisk.rules）
     内置 23 条确定性规则（21 条段落规则 + 2 条缺失性规则），对段落逐条匹配，
     输出按 4 个维度归类的扣分明细（每条含理由、规则编号、原文摘录、整改建议）。
  3) 差异比对层（lawrisk.diff）
     differ 负责章节对齐与段落级 diff（difflib，Myers 风格），sidebyside 负责把
     差异树展平为左右对齐的行（含词级增删高亮），markdown/html/docx 三个报告模块
     负责渲染各格式报告，single_report 负责单文档审阅报告。
  4) 业务接口层（lawrisk.api）
     FastAPI 应用，对外提供 REST API，负责文件接收（含 20 MiB 大小限制）、
     调用引擎、组装响应（含可选的 LLM 摘要，默认关闭）。
  5) 展示层（前端 SPA）
     React 19 + TypeScript + Vite 构建的单页应用，提供上传、评分、比对、
     模板对照、单文档审阅、规则手册查询等交互界面；构建后作为静态资源挂载
     到 FastAPI 同端口对外服务。
  6) 客户端访问方式
     既支持浏览器访问 Web 界面，也支持通过 lawrisk-cli 命令行离线使用
     （score / review / diff / rules 四个子命令）。

系统同时支持两种服务形态：
  - 开发形态：uvicorn 启动 API（:8000） + vite dev server（:5173，HMR）。
  - 生产形态：frontend 构建产物挂载于 FastAPI 同端口（lawrisk.serve / mount_spa），
    仅一个进程即同时对外服务页面与 API。

2.3  接口设计
2.3.1  对外 REST 接口（HTTP/JSON）
- GET  /api/health              健康检查，返回 status、engine 版本、llm_enabled。
- POST /api/parse               上传单个文件，返回解析后的段落、标题、字段、词数。
- POST /api/score               传入段落列表（JSON），返回确定性 RiskReport。
- POST /api/compare             上传两份文档，返回差异树、双向风险报告与 Markdown 报告。
- POST /api/diff-text           传入左右纯文本，返回 CompareResult（含风险面板）。
- GET  /api/templates           列出模板库（MSA/SaaS/NDA/DPA）。
- POST /api/templates/{template_id}/compare  上传文档并与指定基准模板比对。
- GET  /api/rules               规则手册：全量规则目录（编号/维度/严重度/原因/建议/种类）。
- POST /api/review              上传单文档，返回按章节归组的审阅结论与三种报告。
（接口入参出参均以 pydantic v2 模型定义，为主干；错误码约定：超限 413、解析失败 400、未找到 404。）

2.3.2  模块间内部接口
- parse_document(data: bytes, document_id: str, filename: str) -> DocParse
- score_document(paragraphs: list[str], document_id: str) -> RiskReport
- build_diff_tree(paragraphs_left, paragraphs_right, label_left, label_right) -> DiffReport
- diff_texts(left, right, name_left, name_right) -> (DiffReport, list[AlignedRow])
- aligned_rows(report: DiffReport) -> list[AlignedRow]
- render_markdown(report, risk_left, risk_right, facts_left, facts_right, label_left, label_right) -> str
- render_markdown_review(name, paragraphs, risk, facts) -> str
- rule_catalog() -> list[dict]（含 engine 版本）
- extract_fields(paragraphs, text) -> list[FieldRun]

2.4  数据库设计
本系统定位为本地离线工具，不依赖外部数据库。全部数据为进程内结构：
- 变量在内存中的表现：list[str] 段落、list[Penalty] 扣分明细、
  list[DimensionScore] 维度得分、list[DiffNode] 差异树节点。
- 模板库数据以纯文本文件形式随程序打包（versioned with the repo），
  每个模板带有确定性内容哈希便于校验。
- 不维护持久化事务数据；如需审计留痕，可导出 Markdown/DOCX/HTML 报告存档。
（若后续引入服务端存储，建议使用 SQLite 单文件库，接口模型已预留 id 字段。）

────────────────────────────────────────
3  详细设计
────────────────────────────────────────
3.1  数据模型设计（lawrisk/models.py）
- 枚举 Dimension：COMMERCIAL / LIABILITY / DATA / EXPORT，映射为字符串便于 JSON 传输。
- 枚举 RiskLevel：LOW / MEDIUM / HIGH，由总分阈值决定。
- Penalty 模型：dimension、reason、rule_id、severity、excerpt（原文摘录）、
  para_index（命中段落号）、keyword（命中词）、mitigation（整改建议）。
- DimensionScore：维度归一化得分（0-100）、所属扣分明细 rows、reasons 列表、confidence。
- RiskReport：document_id、overall_score、overall_level、dimensions、penalties、summary、
  deterministic_hash（SHA-256）。
- 差异部分：DiffOp（add/delete/modify）、DiffItem、DiffNode（section 级树节点）、
  DiffStats（增/删/改计数）、DiffReport（document_left/right、sections、stats）。
- 字段模型 FieldRun：name、value、source（来源原文）、para_index、found。

3.2  风险引擎设计（lawrisk/rules.py）
3.2.1  规则数据结构
每条规则由 Rule 对象描述：
- rule_id：如 R-COMM-1（维度-序号），全库唯一。
- dimension / severity（1-3 档）/ reason（通用理由模板）/
- pattern（编译后的正则表达式，断言命中关键词）/
- negative（反向排除正则，如"不自动续约"抵消自动续约判定）/
- keyword（显示用关键词）/ mitigation（整改建议）/ kind（paragraph 或 absence）。
规则库当前共 23 条：商务维度 8 条（自动续约、单方终止、单方改价、单方修订、
转让限制、逾期利息、费用不退、单方停服），责任维度 6 条（责任上限、免责、无断供
保证、违约金、差额损失排除、保修免责等），数据维度 5 条（数据处理无范围、GDPR/DPA
缺失、数据跨境、处理条款缺失、留存期限），出口维度 4 条（制裁地区、出口管制、管制
承诺缺失等）；其中 absence 规则 2 条（R-DATA-4、R-EXP-4）判定"应有条款的缺失"。

3.2.2  评分算法（确定性、可复现）
步骤：
 1) 对每个段落 str，依次与每条 paragraph 规则匹配：pattern.search 命中且
    negative 未命中（或规则允许反向语义）则产生一条 Penalty；
 2) absence 规则基于标题/话题结构扫描整份文档，命中时锚定到正文段落
    （跳过标题行，保证摘录引用的是条款正文）；
 3) 按维度聚合：维度分 = min(100, 扣分合计 × 系数)，扣分合计 = Σ severity × 权重；
 4) 总分 = Σ 维度归一化分 × 维度权重（commercial 0.35 / liability 0.30 /
    data 0.20 / export 0.15），再整体映射到 0-100；
 5) 由总分定级：>= 66 为 HIGH，>= 33 为 MEDIUM，否则 LOW；
 6) 计算确定性哈希：对"内容摘要 + 引擎版本"取 SHA-256 前若干位，
    相同输入必然相同输出（已由测试锁定）。
每条扣分均含 reason、rule_id、severity、excerpt（逐字原文）与 mitigation，
满足"可解释性"硬要求。

3.2.3  关键词库与匹配
段落文本先经 normalize 统一小写、压缩空白；规则正则对归一化文本做 search 匹配，
从而兼容大小写、前后空格差异。反向规则（negative）用于排除"本条看起来像风险、
实为正常约定"的句子，显著降低误报。

3.3  文档解析设计（lawrisk/parser.py、textutil.py、fields.py）
- 格式分派：按文件后缀（.pdf -> pypdf、.docx -> python-docx、其余 -> UTF-8 文本）；
  DOCX 解析除正文段落外还读取表格单元格，避免条款遗漏。
- 段落切分：按空行 split_paragraphs 得到段落；looks_like_heading 依据
  头部正则（第X条/第X章/数字编号）识别章节标题。
- 字段抽取：CurrencyDetector / TermYearsDetector / GoverningLawDetector /
  ArbitrationDetector 四个检测器逐一扫描全文，返回字段名、值、来源原文与段落号，
  用于合同关键事实面板。

3.4  差异比对设计（lawrisk/diff/differ.py）
 1) split_sections：将左/右文档按标题切分为章节；
 2) _match_sections：以标题签名为基准，用最长公共子序列（LCS）对齐两文档章节；
 3) diff_paragraphs：在已对齐章节内，用 difflib.SequenceMatcher 对段落做增/删/改
    判定；修改项再经 word_diff 得到词级差异 token；
 4) 每个变更生成 DiffItem（op、左右段落号、正文、语义摘要）；
 5) 语义摘要由关键词驱动（_build_summary / _SUMMARY_FACTS）生成可读的中文描述，
    如"新增了不可抗力条款"。
sidebyside.py 将 DiffReport 展平为 AlignedRow，供 Web 端并排展示并计算改动数。

3.5  报告渲染设计
- markdown_report.py / single_report.py：按规范渲染 Markdown 审查/差异/审阅报告；
- html_report.py：生成自包含 HTML（内联样式、索引锚点），浏览器可直接打开；
- docx_report.py：用 python-docx 生成 .docx，设置正文字体与标题层级；
四种报告均引用真实段落原文与规则理由，保证可追溯。

3.6  前端设计（frontend/src，React 19 + TS）
- App.tsx：全局状态（上传文件、加载态、视图模式：评分/对比/模板对照/审阅/规则手册）；
- types.ts：后端模型的 TS 镜像；
- api.ts：fetch 封装（multipart 上传与 JSON 调用）；
- components/：DiffView（并排视图与差异树）、RiskPanel（评分详情与维度条）、
  VerdictBanner（结论横幅）、TemplatesPanel（模板库）、RulesPanel（规则手册查询）、
  FactsPanel（关键事实）、ReportView / ReviewView（报告与审阅视图）、DiffTree（树视图）。

3.7  关键流程
3.7.1  评分流程
上传 → 解析 → paragraphs → 规则匹配（23 条）→ Penalty 列表 → 分维度聚合 →
总分与等级 → RiskReport → 前端 VerdictBanner + RiskPanel + 报告导出。
3.7.2  比对流程
上传两份 → 分别解析 → 章节对齐 → 段落 diff → DiffTree 与 AlignedRow →
双向风险面板 → Markdown/HTML/DOCX 报告。
3.7.3  单文档审阅流程
上传一份 → 解析 → 评分 → 按章节归组 findings → 审阅报告（Markdown/DOCX/HTML）。
3.7.4  离线命令行流程
lawrisk-cli score/review/diff/rules：直接读取本地文件走同一套 parse → score → diff
管道，输出文本或 JSON，不依赖网络。
